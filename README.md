# 叶脉量化实验室

这是用于透明叶PNG/JPG的本地实验工具。它会提取叶脉骨架、分叉节点、端点、封闭网格、方向熵和局部复杂度热图。

## 启动

双击 `start.command`。工具会在浏览器中打开：

`http://127.0.0.1:8765`

第一次运行时，如果macOS询问是否允许终端访问桌面，请选择允许。

## 在线部署与团队更新

项目已支持以 Docker 方式部署到 Railway。线上数据目录通过
`LEAF_DATA_DIR` 与代码分离，因此更新程序不会删除成员上传的叶片或导出结果。

详细步骤见 `DEPLOYMENT.md`。日常更新只需测试、提交并推送到 `main` 分支，
Railway 会自动发布新版本。

## 文件结构

工具默认读取相邻目录：

`../leaves_origin_images/`

导出的结果写入：

`../analysis_output/`

每片叶会输出原图、叶脉响应、二值叶脉、骨架、节点叠加图、复杂度热图、指标JSON和节点图JSON。批量分析还会生成 `summary.csv`。

## 指标说明

- 实验复杂度：0–100的探索性组合值，目前用于同一批样本的相对比较。
- 归一化叶脉长度：总骨架长度除以叶片面积平方根。
- 分叉节点：骨架中三个或更多方向相接的节点簇。
- 端点：骨架中只有一个相邻像素的节点。
- 封闭网格：二值叶脉形成的闭合区域。
- 方向熵：叶脉方向的多样性，0–1。

当前结果不是植物学鉴定结论。参数与复杂度权重需要通过人工标注和更多样本继续校准。

## 语言算法

从叶片工具右上角进入“语言算法”，或访问：

`http://127.0.0.1:8765/language`

输入英文单词后，工具会输出：

- 字母信息复杂度
- 拉丁大写字形结构复杂度
- 前缀、词根、后缀的启发式切分
- 可编辑的词根语义假设
- 单词综合复杂度
- 主叶脉上的词素布局
- 每个字母对应的分支阶数、侧脉数量和目标叶区分位

词根语义表位于 `language_data/root_lexicon.json`。其中的分数是艺术研究假设，不是客观语言学等级。

版本 0.2 还包含本地离线词汇库与可逆编码：

- Open English WordNet 词义、多义性与词类
- MorphyNet 派生词及屈折变化
- wordfreq 词频数据
- A–Z、空格、撇号、连字符的固定 5-bit 编码
- 帧偶校验和 CRC-10 整体校验
- 结构化数据的编码、解码与完整性验证
- 每帧五根编码载体叶脉，以及由语言复杂度控制的三级叶脉和网格
- 从生成 SVG 中重新读取编码载体并自动验证原词

版本 0.4 将生成单位升级为“一片叶子对应一段文本”：

- 主叶脉承载全文顺序
- 一级分支对应自然段
- 二级分支对应单词
- 单词分支上的微叶脉对应字母编码
- 单词、自然段和全文分别具有 CRC-10 校验
- Language Engine 可以选择任意已分析叶片作为生成风格
- 同一份层级文本包可以重新映射到不同样本

版本 0.5 将结构改为更接近真实叶脉的“标点语法”：

- 样本骨架会被转为包含节点、边、宽度、叶脉级别与主脉路径的表面定位图
- 叶片样本决定全部节点、边、分叉和阅读路线，文字不会生成或延长任何分支
- 句号、问号和感叹号划分句子，但只在既有叶脉上留下拓扑标记
- 逗号、分号、冒号与破折号分别使用不同的环、尾部和横杠组合
- 单词不再形成粗大的独立树枝，而是沿固定叶脉遍历路线形成编码网格
- 每个句子开始处使用 SEG collar（相对双分叉包围一个小环）作为拓扑分段标志
- 段落仅在主脉上形成间隔标志，不再生成巨大的段落分支
- 句子 CRC 与全文 CRC 可验证重编码和解码结果

版本 0.6 将文字真正写入连续叶脉：

- 以叶柄为根，沿主脉前进；进入支脉后递归读取子支，再沿原路径返回父分叉
- 外行与回行使用叶脉两侧的微小编码通道，因此视觉和数据顺序都连续
- 删除所有单词椭圆；单词只使用开始和结束双切口
- 每个字符的 5-bit 身份和偶校验直接形成原叶脉两侧的六根微叶脉
- 支脉回行使用固定回转钩标记，标点、SEG 与 CRC 保持独立拓扑标志
- 页面显示当前文字占叶片天然载体容量的比例；容量不足时不改变叶片结构

版本 0.7 引入 Leaf Protocol Header（LPH）：

- 从叶柄开始的前三分之一为赭黄色协议区，其余为绿色正文区
- 黄色区保存协议版本、叶片图指纹、标点与分段位置、密度、自然扰动、Tile 计划和 CRC
- 标点与分段不再以红色图标出现在正文中
- 黄色协议使用对称长短微叶脉，绿色正文使用左右方向微叶脉，因此黑白图也可区分
- 正文自动循环重复并填满全部绿色载体；Header 记录原始长度、完整重复次数和尾段
- 多个 Tile 副本可以进行多数投票恢复，短文本的重复不再只是装饰
- Header CRC、Payload CRC、事件表和 Tile 算术均参与自动解码验证

版本 0.8 将语法改为面向像素识别的 Macro-Vein Grammar：

- 完整自然叶脉只作为浅色视觉骨架，数据仅写入达到目标分辨率要求的安全脉段
- 绿色正文使用 MVG-4：左右方向与长短组合形成四种 2-bit 宏符号
- 黄色区改用紧凑二进制 LPH Lite，不再在叶片上绘制标点符号
- 正文使用 zlib 压缩、带地址分块、Hamming(15,11) 单比特纠错和 CRC-16
- UI 可选择 2048、4096、8192 或 16384 px，并按 14 px 最小间距重新计算容量
- 放不下一份完整 Header 或 Payload 时直接报告容量不足，不再缩小符号伪造“铺满”
- Tile 只增加完整副本；未使用的自然叶脉保留为空白骨架
- 合成退化测试覆盖缩放、模糊与 JPEG 压缩下的 MVG-4 分类

版本 0.9 改为主脉协议与支脉正文：

- 删除前三分之一黄色分区，黄色协议沿完整主叶脉连续排列
- 英文先通过高频词、离线词典、标点短码和 UTF-8 Escape 进行可逆词汇压缩
- 正文不再生成垂直毛刺，而是把既有支脉设为四种状态：两种绿色深浅 × 两种线宽
- Node Overlay 提供支脉边界与读取地址，支脉按照叶柄到叶尖排序
- 标点、空格和段落直接保存在词汇流里，不再重复写入 Header 事件表
- 禁用 Tile 铺满；没有数据的叶脉保持浅色自然骨架
- 当前 Acanthopanax 样本的约 80 词基准可在 8192 px 下通过容量与回读验证
- CRC-16 负责损坏检测，独立校验支脉将在后续版本加入

版本 0.9.1 优化主叶脉协议外观：

- Header 删除可从图结构重新计算的字段，由 188 个状态压缩到 72 个状态
- 删除主脉两侧的协议短线和所有支脉起点圆圈
- 主脉本身使用两种赭黄色调与相对自然锥形约 ±14% 的宽度变化编码
- 协议分段优先吸附到天然主脉节点，不再使用完全机械的等距节奏
- 只保留叶柄开始环与叶尖双切口结束标志
- 连续锥形主脉的缩放、模糊与 JPEG 合成识别测试达到 96% 以上

版本 0.9.2 加入不改变编码几何的表面渲染器：

- Beauty 模式把原始透明叶片作为对齐遮罩，加入受限的叶面颜色、细噪声、漫反射、高光和叶脉浮雕
- Encoding 模式显示未经材质处理的黄色协议主脉、绿色正文支脉和浅色未使用骨架
- Normal 模式提供法线风格的表面与叶脉高度预览，便于继续开发独立纹理导出
- Data mask 模式在黑底上隔离黄色协议和洋红正文载体，便于阈值、配准和机器读取
- Relief、Light angle 与 Translucency 只控制编码层下方的视觉表面；不会位移、重采样或重写协议和正文状态
- SVG 保存固定的编码签名，切换视图和调节材质时签名保持不变
- 当前阶段不使用 displacement；像素解码完成前，所有会移动编码边界的效果都保持禁用

版本 0.9.3 将 Encoding 确立为单 PNG 最终载体：

- 主叶脉协议由赭黄色改为与正文同源的两档绿色与两档相对宽度
- 叶柄端圆环与叶尖端双切口负责主脉定位；两点之间的连续最强路径即协议主脉
- 固定起始同步序列 `00–11–10–01` 与反向结束序列提供方向确认及深浅、粗细校准
- 解码器应先识别首尾记号，再追踪主脉，不把机器学习作为基础依赖
- Encoding PNG 是最终可解码目标；Beauty 在完整像素回读通过前仅作为展示预览
- 最终验收必须从导出的单张 PNG 重建协议和正文，不允许读取原始内存数据包

版本 0.9.4 加入通用 PNG 样本接入：

- Leaf Analysis 和 Language Engine 都可以直接上传 PNG，新样本会同时出现在两个页面
- 上传后自动完成文件验证、叶片遮罩、叶脉提取、节点图、主脉路径、指标与图文件导出
- 优先使用透明背景，也支持 NMNS 风格的平坦白底或黑底图像自动抠叶
- 每个样本拥有独立的 `metrics.json`、`graph.json`、主脉、支脉地址和容量，不再复用第一个样本缓存
- 默认参数无法生成主脉时会尝试备用灵敏度与对比度组合，并选择拓扑质量更好的结果
- 上传限制为 PNG、32 MB、120 MP，最小尺寸为 128 × 128
- 现有五个 NMNS 衍生样本全部通过默认建图；白底与黑底轮廓检测重合率分别达到 98.93% 与 97.90%

版本 0.9.5 加入正式 Encoding PNG 导出：

- Language Engine 提供 `Export Encoding PNG`，由后端重绘而不是截取浏览器画面
- 输出包含白色定位背景、浅色天然骨架、绿色正文四态、绿色主脉协议和首尾定位记号
- Beauty 与 Normal 图层不会进入最终编码文件
- 支持宽度为 2048、4096、8192、16384 px 的 PNG，线宽和记号随分辨率同比例缩放
- 导出前强制检查协议 CRC、正文 CRC、分支分配和样本容量；不完整结果会被阻止
- PNG 不嵌入原始数据包或隐藏解码元数据，后续解码器必须只依赖可见像素
- 8192 px 实测输出为 8192 × 6226，服务器栅格化约 1 秒

版本 0.9.6 加入统一 Export Preflight：

- `evaluate_exportability` 同时计算主脉协议需求、正文状态需求和样本安全容量
- 每次映射会一次评估 2048、4096、8192、16384 四档分辨率
- 页面显示主脉与正文两条容量进度、四档 READY/FAIL 矩阵和最低安全分辨率
- 点击矩阵中的分辨率即可重新映射；只有当前档为 Layout-safe 时才能导出
- 协议不足、正文不足和两者同时不足会分别显示 bottleneck 与改进建议
- `Layout integrity` 与尚未完成的 `Raster decode` 独立标注，避免把可布局误称为已证明可从像素解码

算法说明见 `docs/language-system.md`，数据许可与署名见 `DATA_ATTRIBUTIONS.md`。

## WAV 声音扰动（拓印载体）

- 拓印文字载体通过容量检查后，页面会出现可选的第 4 步 `Sound`
- WAV 在浏览器中提取能量、峰值、噪声、亮度与撞击点，原始音频不会上传到服务器
- 量化后的声音数组只扰动叶片内部已经识别出的 Lab 颜色载体单元
- `Original / Clean / Disturbed / Difference / Confidence` 五个视图用于比较像素变化
- 最终导出为单张扰动 PNG，服务器会从这张 PNG 重新运行颜色解码和 CRC 验证
- `Preserve / Trace loss / Breakdown` 控制声音驱动的语义偏差；默认只改变少量单词内部字符，保留空格、标点和句子结构
- Transport CRC 验证 PNG 读取是否正确；Source CRC 单独标记恢复文字是否已经偏离原文
- 声音扰动目前只适用于 Leaf rubbing；NMNS scan 继续使用独立的天然叶脉图编码管线

## 诗句归档自动化

在 macOS 上双击 `build_poetry_archive.command`，或运行：

```bash
python3 scripts/build_poetry_archive.py
```

程序会读取项目根目录的 `text_demo_copy*`，以可重现的随机顺序均衡分配拓印叶片与 WAV，
然后在 `poetry_leaf_archive/`内建立时间戳归档。每条诗句包含六张透明 PNG、透明声波图、
原句与 Hard decode 结果、JSON 记录；整批还会生成 UTF-8 CSV 索引和完整 JSON manifest。
